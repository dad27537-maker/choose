# 骰间（Plugin Deck）设计与实现路线

骰间是一个桌面优先、会话优先的插件容器。用户在会话中输入一件事情，插件以交互卡片的形式给出结果。第一款插件是「命运 D20」：安全随机地生成 1–20 的点数，并用电影化骰子动画呈现。

## 当前实现

- React + TypeScript + Vite 的会话式 UI
- 左侧导航、会话列表、插件中心和设置页
- 动态插件清单模型，启用/停用状态持久化
- D20 决策骰：输入、动画、结果、倾向、历史记录和复制
- 浅色/深色模式、移动端布局、减少动态效果
- 本地优先存储；浏览器存储不可用时不阻塞主流程

当前插件仍以内置模块形式打包，作为未来外部插件加载器的兼容实现。

## 分层设计

```text
桌面恢复内核
├── 启动、插件加载、权限代理、安全模式
├── 服务注册中心、事件总线、诊断日志
└── 配置 Profile
    ├── Shell UI
    ├── Session Store
    ├── Plugin Manager
    └── 命运 D20
```

恢复内核保持最小且稳定。导航、会话、存储、主题、通知和具体工具都通过插件贡献，宿主不再为每个插件增加条件分支。

## 插件契约

`src/types.ts` 中的 `PluginManifest` 是 UI 层的稳定描述，后续外部包可以直接映射到它：

```ts
type PluginManifest = {
  id: string
  name: string
  description: string
  icon: string
  version: string
  apiVersion: string
  entryPoint: string
  capabilities: string[]
}
```

运行时插件应提供：

1. `activate(host)`：注册路由、命令、消息渲染器和事件监听。
2. `deactivate()`：撤销所有注册并停止后台任务。
3. `dispose()`：释放视图、音效、计时器和 WebGL 资源。
4. 每项能力声明对应的权限和依赖。

未来的包格式建议为 `.dpk`：`manifest.json`、UI bundle、资源和签名。第三方插件先在独立 WebView/Worker 中运行，通过 JSON RPC 与宿主通信；文件、网络、通知等能力由宿主权限代理授予，不能直接注入主 WebView 或加载原生 DLL。

## D20 规则

随机点数在动画开始前生成，使用 `crypto.getRandomValues` 和拒绝采样，避免取模偏差。动画只负责呈现已经提交的结果，因此帧率或碰撞差异不会改变点数。

默认倾向映射：

| 点数 | 倾向 |
| --- | --- |
| 1 | 大失败 |
| 2–5 | 不建议 |
| 6–10 | 偏向不做 |
| 11–15 | 偏向去做 |
| 16–19 | 建议 |
| 20 | 大成功 |

20 面模型使用艺术化低多边形造型，概率由程序保证；后续可将 GLB 模型替换为正式美术资源，并为每个面保存目标朝向。

## 推荐目录

```text
apps/desktop/              Tauri 桌面壳（下一阶段）
packages/kernel/           生命周期、服务、事件和依赖
packages/plugin-sdk/       插件开发接口
packages/ui-kit/           统一视觉组件
plugins/dice-d20/          第一款插件
```

现阶段仓库根目录的 Vite 应用承载 UI 原型；`Desktop/WorkRoll.Core` 保留为协议研究代码，待 Tauri 壳确定后统一迁移，避免同时维护两套 UI 和插件协议。

## 实施顺序

1. 接入 Tauri 2，建立 Windows 桌面窗口、托盘、安装包和更新入口。
2. 将当前静态 registry 替换为 `PluginLoader`、依赖解析和生命周期管理。
3. 把本地存储从浏览器存储迁移到 SQLite，保留插件命名空间。
4. 将 D20 的结果事件写入会话事件流，实现恢复、搜索和重放。
5. 接入正式 20 面 GLB、音效和更细的落地动画。
6. 增加第三方插件包、权限确认、签名校验、崩溃隔离和回滚。

## 验收标准

- 用户可以输入任意事情，并通过 Enter 或按钮完成投掷。
- 每次结果严格落在 1–20，重启后记录仍可查看。
- 1 和 20 显示特殊结果，其余点数显示默认倾向。
- 插件可以在设置页停用和恢复，停用不删除历史数据。
- 减少动态效果时仍能直接看到结果。
- 单个插件渲染或存储失败不会让宿主白屏。
- 第三方插件没有声明权限时不能访问文件、网络或系统能力。
